## Architecture Decisions

- Auth is Clerk, protected by default at the proxy level (`proxy.ts`, allow-list of public routes) rather than per-page checks — matches 03-auth.md's "protect everything else by default" requirement and keeps future routes secure without remembering to add checks.
- Authorization for Project/ProjectCollaborator data is enforced at the application layer (every Prisma query filtered by the Clerk `userId` from `auth()`), not Postgres RLS — there's a single trusted `DATABASE_URL` connection, not per-user DB roles. Applied in `06-project-apis.md`'s routes: list is scoped by `where: { ownerId: userId }`; rename/delete fetch-then-compare `project.ownerId !== userId` before mutating, returning `403` on mismatch and `404` if the project doesn't exist.
- Rate limiting deferred for the Project CRUD routes (06-project-apis.md) — internal, Clerk-authenticated editor feature, no public/anonymous surface or per-call paid resource. Revisit if these routes become public or see abuse.
- Mutations from the editor UI (07-wire-editor-home.md) don't hold client-side project-list state — the editor home page is a server component that fetches owned/shared projects on each render, and the `useProjectActions` hook triggers a `router.refresh()` (rename/non-active delete) or `router.push` (create success, delete of the active workspace) to get fresh server data rather than reconciling an optimistic local list. Simpler and matches the spec's "no client-side fetching for initial load" intent extended to post-mutation state.
- `types/project.ts`'s `Project` dropped its `slug` field (leftover from 04's mock-only implementation) — the real `Project` Prisma model has no slug column. The "room ID preview" shown in the create dialog is a client-only `slugify(name) + "-" + shortRandomSuffix` computed in `useProjectActions`, purely cosmetic; the actual workspace URL uses the real DB-assigned `project.id` returned by `POST /api/projects`, per the spec's "project ID and Liveblocks room ID should stay aligned."
